## 缺口与冲突

1. **驱动冲突（R545）两方原文**：均已取得且逐字核对（见 NVIDIA 表第 4 行），release 25.01 页 Driver Requirements 与 Support Matrix 25.01 列文本完全一致——第一段允许数据中心 GPU 用 545.23+ (R545)，第二段把 R545 列入「not forward-compatible with CUDA 12.8、应升级」。新增部分裁决证据：Forward Compatibility Table 3（页脚 2026-09-09）中 cuda-compat-12-8 仅对 535+ 标 C，表注称未列分支 EOL 且不是兼容包支持目标，R545 不在表内。该表收窄了「兼容包路径下 R545」的解释空间，但没有一处官方文本把第一段（可用 R545）与第二段（应升级 R545）显式调和；冲突保持 `conflict`，不能拼成「R545 已支持」。
2. **Python 冲突两方原文**：均已取得（release 页首段 `/usr/local/lib/python3.10/dist-packages/torch` 与 Contents「Ubuntu 24.04 including Python 3.12」同页并存）。NGC catalog 的 PYVER=3.12/PYVER_MAJMIN=312 本轮无法经 FetchURL 复核（JS 渲染，仅得 cookie 横幅；api.ngc.nvidia.com 候选端点 404/500），仍以 2026-09-30 登记的浏览器观察为准。
3. **新发现跨页差异（轻量）**：release 25.01 页 Contents 写 TensorRT Model Optimizer **0.21**，Support Matrix PyTorch 容器 25.01 列（列归属经 HTML 解析确认）写 **0.17.1**，同页其他字段（PyTorch 构建、Python 3.12、RAPIDS 24.10、TE v1.14 等）一致。按冲突处理流程记录双方位置，不擅自取其一。
4. **页面变化审计**：rel-25-01.html 的页脚与 `nv-pub-date` 现为 2026-09-29，而 2026-09-30 登记时记录为「last updated 2026-09-08」；Support Matrix 与 User Guide 同为 2026-09-29；minor-version 与 forward-compatibility 页脚为 2026-09-09，且 minor-version 页已含 CUDA 13.x 行（登记时未记）。抽查的关键主张（Contents、驱动两段、python3.10 路径、>=525 行）未变。日期回写与内容演进支持在 compatibility-evidence 中要求记录「页脚/元数据日期 + 观察日期 + 关键字段抽查」三件套。
5. **CANN-驱动配套交集：部分取得**。已取得 CANN 版本兼容性页（8.3.RCX ↔ HDK 25.3.X/25.2.X/25.0.X/24.1.X/24.1.RC3，系列级通配）与 TorchNPU 7.2.0 版本兼容性页（7.2.0 ↔ 六个 CANN 版本，DrivingSDK 7.2.RC1 ↔ CANN 8.1–8.3.RC1）。**未取得**：CANN 8.3.RC1 钉到精确驱动/固件版本的官方静态表（ModelZoo 表无 8.3.RC1 行；MindSDK 摘要提示 25.3.RC1 但未一手核对；hiascend 下载中心与兼容性查询助手均为 JS/交互，静态抓取不可得）。OS×机型的精确交集（兼容性查询助手结果）同样未取得。Ascend 档案的「精确 HDK」「OS 交集」补齐子项应继续保持阻塞。
6. **机型位置**：Atlas 800T A2 在固定 TorchNPU README 硬件表内（A2 训练系列）；Atlas 900 A3 不在该固定快照硬件表内，但 CANN 快速安装页产品选择器含「Atlas A3 系列产品」且默认命令展示 `a3-cann-kernels==8.3.RC1`——A3 的 CANN 侧安装支持有文档入口，A3×TorchNPU 固定快照的组合在该快照内无声明。
