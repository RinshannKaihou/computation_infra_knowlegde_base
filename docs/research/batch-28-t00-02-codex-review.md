## 发现清单

### C01 · P2 · 将共享上游直接写成全域或固定作业影响，超出已核故障域证据

- **位置**：正文 L84、L95、L99、L111；作者取证记录 L9–10 的“故障域”支持范围。
- **证据**：L95 断言列举部件“任一故障影响整个域或其大部分”；L99 又称 A3 故障域与 GB200“同构”。但[资源拓扑](../../knowledge/01-hardware/resource-topology.md) L276–281 把这些逐层列为待验证假设：A3 L1 总线板位于节点内、先按节点边界提出假设；NVL72 power shelf 为 N+N，不能按任一 shelf 失效等同全域故障；switch tray 失效影响没有量化口径；A3 的实际冗余配置是变量。L111 的“节点故障影响单作业分片”也把物理受损范围等同应用影响，未考虑 collective/作业组依赖；所链[分布式推理布局](../../knowledge/07-inference/distributed-inference-layouts.md)的单副本失败验证段明确要求核对参与组和其余副本进展。
- **建议**：区分节点内、跨节点、机柜及跨柜的候选共享组；分别记录部件、依赖成员、冗余前提、可能失效模式与影响未知项。把确定全域结论改为条件性故障传播假设，删除跨厂商“同构”影响断言；物理损坏、通信域退化和作业/服务影响分列。
- **关闭条件**：正文与取证记录不再由共享关系直接推出影响大小；保留 N+N、L1/L2 与实际配置边界，未取得映射的影响写 unknown/待验证。无需为本次修订执行故障注入。

### C02 · P2 · 比较表把未核性能、成本与适配条件写成系统形态的固有结论

- **位置**：正文 L109–114，尤其 L110、L112–113；与 L129、L133–137 的 unknown 声明冲突。
- **证据**：L113 写 TP/EP 流量“在域内才可承受”，但其直接引用的[分布式推理布局](../../knowledge/07-inference/distributed-inference-layouts.md) L93–108 明确讨论跨机 TP 通信、EP 后端与性能因素，没有给出这种可承受性禁界。[训练并行与状态](../../knowledge/06-training/parallelism-and-state.md) L162 同样把低时延域写为机制性倾向、实际上限取决于模型和互联。表中“网络主导”“成本项最简单”“域内带宽溢价换扩展性”“液冷近乎必然”均未限定到具体样板或给出逐项证据；作者取证 L22 却明确无单价来源。“容量近似线性扩展”未区分原始物理数量/内存合计与作业可用容量、吞吐扩展；两者不能共用结论。8 卡是已列节点样板的例子，也不应成为通用节点域定义。
- **建议**：把表改为待核约束及条件性倾向：明确容量口径，列出模型/布局、通信量与重叠、端到端存储、实际拓扑/拥塞和软件支持等前提；目标系统的瓶颈、扩展收益、价格溢价与冷却需求缺证据时保留 unknown。液冷仅按两个所选样板的组成记录；TP/EP 跨机是否可用及是否满足目标分别核对。
- **关闭条件**：没有无条件的 TP/EP 域内限定、成本排序、线性有效容量/性能或通用冷却保证；数值和定性比较均能定位到指定样板证据或明确标为待检验假设，表格与未知清单一致。

### C03 · P2 · 假设示例仍输出不足以推出的优劣与反转结论

- **位置**：正文 L116；acceptance 3。
- **证据**：示例确已明确“假设、非实测、非推荐”，TP=8/总 64 卡是设计输入而非测量结果，p/r 也没有伪造数值。但“p 超阈值且 r 可接受→B 更优；任一不成立则反转”既未定义“更优”的目标，也未限定 B 的通信实际收益、平台/软件支持、放置隔离与其他成本；条件失效不能逻辑推出 A 更优。DP 层 all-gather 还缺具体策略前提：[训练并行与状态](../../knowledge/06-training/parallelism-and-state.md) L50–58、L160–162 区分普通 DDP 梯度同步与 FSDP `FULL_SHARD` 参数 all-gather，不能仅从 DP 名称推出后者。64 卡超节点候选也未绑定产品/配置，不应由 A3 的逻辑卡数列表推定其可分配给作业的实现（正文 L135 已列该机制 unknown）。
- **建议**：明确 DP/FSDP 等实现和负载、相同资源与质量目标、p 的测量窗口/分母、r 的比较范围及预登记的评价目标。允许候选 B 保持抽象假设，但把域可获得/可放置等作为待核前提。结论改为“满足这些条件才值得进入对照验证”，任一项未知或不满足时保留无法判定，避免自动反转。
- **关闭条件**：示例保留醒目的假设及无实测数值声明，通信操作与策略对应；结论不超出假设逻辑和证据强度，不以两个符号变量绕过完整依赖门槛。

### C04 · P2 · 概念图未清楚分离网络路径与组件部署职责，并新增 BMC 独立性保证

- **位置**：正文 L58–89；acceptance 1。
- **证据**：三图已标原创，但集群图 L70–72 把存储网络和带外管理网络画作“计算/存储网络”的分支，未标明只是逻辑关联还是实际串接/共网，不能清楚表达独立路径。03 域[互联路径](../../knowledge/03-communication/interconnect-paths.md) L122 则明确所选 H100 RA 的四套 fabric 分立；资源拓扑 L91 也说明方框不得暗示计算/存储/管理共用物理网络。L62 的“BMC 独立供电与时钟”无本轮来源支持；带外管理不等于独立供电故障域或可直接对齐的独立时钟，资源拓扑 L181 只支持 BMC/HMC 管理组成。L74 与 L89 给出了调度器名称和物理/逻辑分离原则，但仍缺控制服务、节点执行端、存储服务/客户端、BMC 各部署在哪里及承担什么职责的对应关系；05 域现有[视图对齐表](../../knowledge/05-cluster-platform/kubernetes-job-lifecycle.md)和 [Slurm 职责表](../../knowledge/05-cluster-platform/slurm-jobs-and-device-resources.md)已可用于概念层关联。
- **建议**：分别画计算通信、存储访问、带内控制和带外管理路径；共网/独立网作为需记录的部署条件，配图例说明物理边与逻辑管理边。用简表关联控制服务、节点 OS/驱动/运行时与执行代理、负载进程、存储端和 BMC 的位置/职责，链接 05 域细节，不要求复制完整平台架构。删除无依据的 BMC 供电/时钟保证，改为按目标机型及供电/时间同步证据记录。
- **关闭条件**：三图的边不会被读成未经核实的共网/串接；部署位置和职责有明确关联；带外、控制面与物理独立性不再互相替代，物理组成和调度/服务逻辑可分别阅读。
