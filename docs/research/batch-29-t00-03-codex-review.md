## 发现清单

### C01 · P2 · 训练降频被混作低质量产出，吞吐损失被直接当成错误预算

- **位置**：L57；关联 L49–50、L91/L101，取证记录 L15/L19/L26。
- **问题**：L57 把“因降频/降级完成的低质量 step”放在不按正常产出计的定义中，却未区分仅降频导致的变慢与确实未过质量判据的更新。降频本身不是结果不合格的证据；仍满足训练语义和质量要求、只是耗时更长的更新应计净进展。紧接的“总吞吐与有效进展的差距就是故障预算消耗的直读数”又把产出速率差、重算损失与 SRE error budget 合为一项。
- **证据**：performance-analysis L56 要求说明有效 token/step 处理，L98 要求等有效预算的质量对照，没有按频率判质量。dimensions 页 L40–43 分开性能与正确性。[SRE 的 SLI 与错误预算定义](https://sre.google/workbook/implementing-slos/#what-to-measure-using-slis)要求先定义好事件、总事件、SLO 和窗口；重算 token/s 或丢失 step 不能在没有映射规则时直接成为预算消耗。正文所谓总吞吐还可能与净进展在 pad/过滤处理上不同，差值也未必只由故障产生。
- **关闭条件**：明确“变慢但合格”的更新仍计有效进展；仅按显式质量/状态判据排除不合格更新。将重算量、净进展损失与 SLO 错误预算分别记录；如需建立映射，写清同一有效工作单位、事件分母、窗口和换算公式，否则删除“直读数”。同步修正取证表，不要求为关闭本项实际训练。

### C02 · P2 · goodput 的逐请求条件、窗口分位 gate 与降级可用性没有分开

- **位置**：L50、L58、L108；关联 L118/L122，取证记录 L18/L26。
- **问题**：L58 的 goodput 首句正确，但 L108 再说“goodput 的 SLO 含延迟分位”，没有区分逐请求的 TTFT/TPOT/E2E 阈值与一个窗口的 p99 gate。L58 又无条件把低于质量判据的降级请求计入可用性、排除出 goodput；这两项都必须依据各自事先声明的合格事件定义，而非由“仍在服务”决定。质量 gate 可以作为本库扩展，但不能让读者误以为 07 域所核客户端已经自动做质量判断。
- **证据**：latency-metrics L175–189 明确逐成功请求检查所有已提供的阈值，再除以主窗口时长；分位数统计在其 L217 起另述。窗口 p99 达标不直接给出同时满足多个阈值的请求数。dimensions 页 L76/L81 只说降级结果**可能**计入可用性，需保存降级规则；mitigation 页 L98–101 要求质量降级先有业务门槛。
- **关闭条件**：将“逐请求联合合格条件”“窗口延迟分位 gate”“good completed / duration”分列，并明确质量检查是另加的测量/验收条件。降级请求能否进入可用性分子须绑定所选可用性契约；只有声明质量为 goodput 条件并有对应判定时才据此排除。正文与取证表保持同口径，示例 B 按此定义重述。

### C03 · P2 · 容量三词混合需求与供给，并把空置备用当成全部冗余

- **位置**：L51、L60–64、L79、L105–110；取证记录 L20–21/L26。
- **问题**：资源峰值被定义为“最大占用”，例子同时列 EAP/EPP；EAP 是平均功率需求，不是峰值，也不是可分配资源上限。冗余余量又限定为平时不承载生产的部分，并把“双副本的第二个”一概归入：这漏掉正常时共同承载、故障时靠剩余容量接管的冗余，且与示例 B 的负载摊薄语境不一致。L64 的“余量越大可用性越高、单位有效产出成本越高”没有保留独立性、接管和有效产出条件。
- **证据**：rack-power 页 L46–49 分开平均/峰值需求、失效情景下可承诺的供给及剩余余量，L55/L57 给出不同的预算关系，并非三者都代表最大占用。dimensions 页 L100–102 和 mitigation 页 L115–117 要求核对相关故障；capacity-and-autoscaling L48/L71 明确副本数不保证集群容量线性或可用性。单位有效产出成本还同时取决于冗余减少的停机/损失，不能只凭购置增加判断方向。
- **关闭条件**：对同一资源对象分别定义物理/设计供给上限、负载需求、可承诺/可分配容量与故障余量；EAP 只作为平均需求示例。区分空置备用和运行期共同承载两种实现，说明余量可由故障情景下的剩余 SLO 容量表达。将可靠性/单位成本方向改为带独立性、接管、容量与产出条件的权衡；示例 B 显式声明理想均衡与容量可加等假设，不把 `Nc≥R` 当成接管窗口始终达标的证明。

### C04 · P2 · PUE 换算方向错误，并将降功率直接写成降能耗

- **位置**：L73、L75、L81；关联 L53/L66–75，取证记录 L26/L33。
- **问题**：L75 将“设备级读数除以 PUE”称为作业墙表能耗的估算假设；这不只是估算精度未知，而是对象和换算方向都不成立。L81 又将降频/限功率直接等同“能耗↓”，未固定持续时间或合格产出。
- **证据**：按正文自身给出的 `PUE=总设施能耗/IT能耗`，只在边界/周期相同且已有 IT 能耗时，才能作 `设施能耗=PUE×IT能耗` 的代数换算；PUE 既不是设备到主机的比例，也不能补齐 CPU、主机内存等遗漏项。另由 `E=∫P(t)dt` 可知，功率降低而时间增加时，完成同一有效工作的总能耗可能升也可能降。这是对正文定义的推导，不冒称 MLPerf 给出了 PUE 或降频收益结论。
- **关闭条件**：删除设备功率除以 PUE 的估算说法，分开设备→系统的组件边界与 IT→设施的分摊边界；若保留设施估算，明确乘法方向、同周期能量与分摊假设，实际系数继续 unknown。把限功率的直接效果写成功率约束，单位有效产出能耗由同窗能量和合格产出验证。无需引入价格或设施实测数字。

### C05 · P2 · 设备级功耗范围被写成工具通用性质，内存边界不准确

- **位置**：L70、L136；关联 L12–13/L36，取证记录 L17。
- **问题**：L70 未指定具体功耗字段，就概括 nvidia-smi/DCGM“不含主机、内存、风扇”等。若“内存”包含设备显存，这与所引 NVIDIA 整板读数不符；若仅指主机 DRAM，应明确限定。工具名本身也不足以固定 GPU 板级、模块级或内存子系统级范围。正文没有给这项具体排除清单附近的精确文档入口。
- **证据**：本轮打开的 [nvidia-smi 官方页](https://docs.nvidia.com/deploy/nvidia-smi/index.html#gpu-power-readings)将 GPU 的平均/瞬时读数描述为整板功率；同页还分别列模块功耗（可含受支持 NVIDIA CPU）和 GPU 内存功耗。固定 DCGM [`dcgm_fields.h` L530–543](https://github.com/NVIDIA/DCGM/blob/b0ec3c624ea21e688b0d93cf9b214ae0eeb6fe52/dcgmlib/dcgm_fields.h#L530-L543)只据相应 ID 定义设备 W、累计 GPU mJ、瞬时 W，不能据此推出正文的跨工具排除清单。当前 latest 的模块描述不证明 2026-09-30 页面相同，也不证明这些字段适用于任何 NPU。
- **关闭条件**：按所选字段/实体声明测量边界，将主机 DRAM 与 GPU 显存、机箱风扇与板级范围分开；不从工具名推定所有功耗读数都排除 CPU/内存。补精确来源链接和观察日期，复用登记可保留，但需如实写本次补核范围；NPU 字段和未核机型继续 unknown。

### C06 · P2 · 示例 A 的单位产出成本缺少共同时间基准，利用率与恢复折算可能重复或遗漏

- **位置**：L52、L57、L91、L97–101；取证记录 L26/L31/L34。
- **问题**：L97 的分子含按年折旧及 `8760` 小时的费用，分母却是 tokens/s，结果不是货币/token。`C_energy` 未定义为货币/J、货币/Wh 还是货币/kWh，墙表功率与该系数的单位也无法闭合。`u` 只进电费，没有说明为何不进同一年度产出或 W 是否已含空闲期。另一方面，P 被称为“有效吞吐”，前文又已把故障重算从有效进展中扣除，随后乘 `a'` 可能二次扣损失。
- **证据**：年费用除以秒吞吐在量纲上缺少年度秒数；若功率用 W、电价用货币/kWh，还需 W→kW 转换。对于一个明确的简化模型，若 u 是计划运行时间占比、a' 是这些计划窗口内的净产出折算，年度两机产出应写作 `Q2=2·s·P·u·a'·H_s`，其中 `H_s` 为同一年的秒数；这只是可选定义示范，不能同时又让 P 或 a' 含同一 u/恢复折损。正文目前没有排除这些歧义，故 L101 的乐观相等只能在补全一致假设后成立。
- **关闭条件**：先定义运行期 P、u、a/a'、W 的窗口和是否含空闲/重算，再用同一时间范围的费用与净产出相除；明确年度小时/秒和电价单位，或统一改用货币/秒模型。给出单机与两机对照公式，使各折算恰好使用一次，声明零产出时单位成本不可计算。允许继续用符号并忽略已声明的成本项，无需扩写完整财务模型；L52 的“成本项×折旧期×利用率”也应改为按项计费/折算的说明。

### C07 · P2 · 示例 A 混淆总吞吐收益与单位产出成本的翻转条件

- **位置**：L94、L101；关联 L87 和取证记录 L26/L31。
- **问题**：L101 先正确指出 `s<1` 已使单位成本/能耗按 `1/s` 变差，随后又把“s 低于某阈值，或 a' 损失超过吞吐增益”作为单位成本反而更高的条件，混淆了两种比较目标。节点和费用都翻倍，成本比较中的倍数 2 已抵消，不能拿总吞吐的翻倍作为单位成本的收益抵扣。
- **证据**：在两机成本/功率为单机两倍、u 等其他条件相同、且不重复扣恢复损失的假设下，静态推导为：

  ```text
  两机净产出速率 / 单机净产出速率 = 2·s·a'/a
  两机单位产出成本 / 单机单位产出成本 = a/(s·a')
  两机单位产出能耗 / 单机单位产出能耗 = a/(s·a')
  ```

  因此总净吞吐增加的条件是 `s·a'>a/2`，单位成本更低的条件则是 `s·a'>a`；后者在 `s≤1` 且 `a'≤a` 这一损耗情形下不能成立。总吞吐仍增加而单位成本已恶化完全可能，不需要等待恢复损失吃掉总吞吐增益。这是符号推导，不是性能测量。
- **关闭条件**：在 C06 的口径修正后，分别列吞吐、单位成本和单位能耗的比值及等号/不等号条件，说明 `s≤1` 且 `a'≤a` 时没有单位成本优势可供“翻转”；若假设 a' 改善，也需单独声明依据。若要示范成本优势翻转，可另加并定义不同的设备价格、功率或运行效率假设，不得以新增无来源数值代替推导；同步修正“各例带翻转条件”的取证描述。

### C08 · P2 · 示例 B 的负载强度有量纲错误，且 b* 的下降区间并非必然存在

- **位置**：L80、L105–110，重点 L107–108；取证记录 L26/L31。
- **问题**：`ρ=c(b)` 把无量纲负载强度等同请求/s 容量；“上限逼近”也没定义逼近的是 1 还是服务率。L105 的 c 是同 SLO 下的有效容量，L108 的 `c(b)` 又像不受延迟约束的原始吞吐能力。即便增大 b 提高该能力，也不能据此断言负载强度更高、排队必增，以及必有一个超过后“吞吐升而 goodput 降”的 b*。
- **证据**：在理想均衡的 M 副本简化模型内，应先区分到达率 `λ=R/M` 与单副本原始服务能力，再以 `ρ=λ/c_raw(b)` 定义负载强度。固定 R/M 时，若 `c_raw(b)` 增大，这个 ρ 反而下降；等待凑批、调度策略、长度分布可能引入另一种延迟，但需独立说明。latency-metrics 要求逐请求 gate；capacity-and-autoscaling L47–48 也分开 SLO 容量与总吞吐、并明确集群折损。延迟 SLO 的存在本身不保证有限 b 范围内一定出现下降侧；最佳点也可能在允许范围端点。
- **核实的算术边界**：对 `R>0、c>0、N=⌈R/c⌉`，并额外假设容量可加、接管后均衡，N+1 少一个仍有 `Nc≥R`。购置增幅是 `1/N`；能耗同增 `1/N` 仅在每副本 W 保持同一常量及周期时成立。利用率应写成 `U_N=R/(Nc)`、`U_(N+1)=U_N·N/(N+1)`；`N/(N+1)` 是相对保留因子，不是绝对利用率或下降的百分点。
- **关闭条件**：定义 b、实际服务副本数、每副本到达率、原始能力与 SLO 有效容量，修正 ρ 公式及适用的排队假设；将凑批等待与容量逼近分别说明。将 b* 写为在预登记候选集合/目标下待测的最佳点，或显式加入可产生下降侧的假设，不宣称 SLO 单独保证其存在。补上利用率比值和固定 W 的条件，并与 C02/C03 的 goodput/冗余口径同步；不要求实际压测来关闭这些定义错误。
