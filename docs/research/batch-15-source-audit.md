## 修订后的重点边界（2026-10-09）

- **memory.events 时间窗差分与空间归因分开（B15-C01）**：`memory.events` 是层级累计——同路径前后差分只消除窗口开始前的累计量，**不消除后代 cgroup 的贡献**；归因须用目标身份对应范围的 `memory.events.local` 差分，或明确叶子/后代范围并结合被杀 PID、cgroup 身份与 OOM 日志（反例：父级两个子组、仅非目标子组被杀时父级差分照样增长）；`oom_kill` 计入任一种 OOM killer，其增长不单独证明 memory.max 限额 OOM；`memory_localevents` 为 legacy 挂载选项、默认含子树计数。
- **FDSize 是描述符表槽位容量（B15-C02）**：`FDSize`＝「number of file descriptor slots currently allocated」，是已分配槽位/容量信息，**不是当前打开 FD 数**，不作 RLIMIT_NOFILE 使用率判据；FD 占用核对用 `/proc/<pid>/fd`（受权限约束、并发开关 FD 时为采样值）；RLIMIT_NOFILE 保留「可分配 FD 编号上界」语义。
- **EMFILE/ENFILE/EPERM 三层分列与 EPERM 三候选（B15-C03/C08）**：EMFILE=进程 `RLIMIT_NOFILE`（open(2)）；ENFILE=系统级打开文件表（file-nr/file-max 与 printk 为该层辅助证据，不是 EMFILE 的含义）；setrlimit/prlimit 报 EPERM=限额调整失败且**不反推唯一原因**——三种候选分列：非特权进程提高硬限缺 `CAP_SYS_RESOURCE`、硬 `RLIMIT_NOFILE` 提到 `/proc/sys/fs/nr_open` 之上、`prlimit()` 调用者无权设置目标 PID 限额（反例：请求值低于 nr_open 但无权提高硬限同样报 EPERM）；判别须结合 resource、原软/硬限、请求值、nr_open、调用者能力与目标 PID 权限，证据不足保持 unknown；诊断记录须写失败的具体系统调用（open/pipe/dup/setrlimit…），不只记 errno 名。
- **设备打开 errno 候选化（B15-C04）**：EPERM 是候选层提示——cgroup v2 设备控制器（BPF，拒绝返回 -EPERM）与 seccomp（OCI `defaultErrnoRet` 默认 EPERM；`SECCOMP_RET_ERRNO` 可在系统调用未执行时返回）均可产生，逆向推断不成立；EACCES 指向 DAC/组权限方向但不能单独证明 udev 问题；cpu-manager 重置 device cgroup 的历史案例归入「节点在但打开被拒→访问许可」分支并保留 K8s 1.12/CentOS 7.6 历史限定；收敛须联合设备身份、DAC/组权限、设备控制策略、seccomp 配置与安全审计证据。
- **hipStreamDestroy 两种销毁时机、不建取消保证（B15-C05）**：上游原文为队列可在仍有 in-flight 命令时被销毁、或等全部排队命令完成后再销毁；删除「允许 in-flight 命令随队列删除」的扩写——该段不建立任务取消保证、不能据此认为缓冲区可安全释放；销毁/同步/资源释放三个概念分别核对（CUDA 立即返回+完成后自动释放、HIP 两种时机+未单独承诺释放、CANN 显式销毁/复位时默认 Context 任务先完成再释放）。
- **NVSM 图像证据链限定口径（B15-C06）**：§3.8.4 正文泛述（组件清单）与示例图像机型限定分列——NIC 压测限 DGX-1/DGX-2/Luna（示例输出中的历史限制，不外推为当前全部机型支持矩阵）、非支持平台该组件结果空白、示例结果表 NIC=SKIPPED；`--no-prompt` 对确认提示的抑制作用为已取得说明（不推导完整行为与 `--force` 含义）；三项图像内容统一标注「编写者对官方 PDF 图像页的核对记录（600 DPI 渲染 OCR），独立审阅者两轮图像调用失败、未独立核验」，PDF URL 与页码保留待后续独立复核；`DURATION` 单位继续 unknown；DGX H100/H200 quickstart 不能补足 NIC 压测支持证明。
