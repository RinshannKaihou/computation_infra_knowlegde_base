## 对照方法与缓存身份（跨平台汇总，均来自上表来源）

- 基线一致性要求（GPU 主样板）：Dynamo guard 检查输入 type/device/dtype/shape/stride/requires_grad（TENSOR_MATCH 示例）；Inductor 缓存官方声明同 PyTorch+Triton 版本、同 GPU、同图、同输入形状、同配置；固定测试观察到图与 guard 同时变化时 cache miss 不误复用（反例 B，B16-C04 后收窄：不能隔离证明 guard 值独立入 key，该证据未取得）、`max_autotune` 配置变化产生不同缓存项（反例 D）。
- eager 对照：GPU 侧官方消融链 backend="eager"→"aot_eager"→"inductor"（+mode/dynamic 变体）；NPU 侧官方 `config.debug.run_eagerly=True`（FX graph 级 eager 定界）。两者层级不同，不可互换表述。
- warmup/稳态：GPU 侧「前一两次调用显著更慢」+ CUDA Graphs 捕获前 side-stream warmup；CUDAGraph Trees 三次调用语义（warmup→录制→replay）；NPU 侧 720 文档树未找到独立的 warmup 章节（缺口）。
- 回退后行为：GPU 侧超 cache_size_limit（8）回落 eager 并告警；NPU 侧 vLLM-Ascend 文档建议 enforce_eager（src.ascend.vllm-ascend-v0-14-0rc1，第十一批已取证，训练侧不可外推）。
- 权重/地址一致性：GPU 侧 CUDAGraph Trees 对参数/buffer 假定地址不变并运行时检查；NPU 侧 frozen_parameter / mark_static_address（PyTorch v2.6.0+）显式固定权重类输入地址。

- **FAQ 与代码默认值不一致**：torch.compile FAQ（2.6）称 "CUDA graphs with Triton are enabled by default in inductor"，而 v2.6.0 代码 `torch/_inductor/config.py` L889 `triton.cudagraphs` 默认 False（env TORCHINDUCTOR_CUDAGRAPHS 控制），实际由 mode="reduce-overhead"/"max-autotune" 开启（torch.compile API 页）。正文按「默认关、由 mode 开启」写，FAQ 句标注为文档表述差异。
- **ROCm 文档线缺口**：docs-10.1.0 无 pytorch-compatibility 页（404 实测），ROCm 10.1.0 文档体系内未找到 torch.compile/Inductor 专项说明页（ai-ecosystem 安装页无相关内容全文检索为空）；可用的固定版本证据为 PyTorch 2.6 上游概括声明 + HIP graphs 文档 + 10.1.0 release notes 的 CK-for-Inductor 条目；7.2.3 兼容性页与 10.1.0 样板不同版本线，只能对照引用。ROCm 上 torch.compile 的逐项限制（如 Inductor 算子覆盖、Triton ROCm 版本配套 pytorch-triton-rocm）未固定到官方文档，保留 unknown。

- **"The dynamic shapes manual" 是 Google Doc**：2.6 文档页外链的可变文档，未固定、未采用；动态形状结论仅引 docs/2.6 页面。

- **issue #137414 的修复证据未展开**：仅核对 state/labels/时间作存在性证据；修复 PR 与回归测试未追溯，不能写成「已修复并验证」。
