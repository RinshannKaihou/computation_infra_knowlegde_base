## 缺口与冲突

- **CANN 编译器组件职责页缺口**：Toolkit 包描述含「开发和编译」职责，但 Ascend C 编译器/图编译器的独立职责页（8.2/8.3 树）本轮未定位取证；对照矩阵 CANN×编译格的「平台声明」只能引用包级描述，不得写成组件级结论。
- **HCCL 版本线不齐**：本批 HCCL 职责表述取自 82RC1alpha001 树（与 AscendCL 接口页组同树）；83RC1 树对应页未核对；已登记 HCCL 文档为 8.0.RC1.alpha003（API 参考 PDF）与 8.1.RC1.alpha001（用户指南 PDF）两条其他版本线。正文引用必须带树版本限定，三线不可混。
- **AscendCL 自述偏推理**：aclcppdevg_000001 以「开发深度神经网络推理应用」为主语；训练路径（TorchNPU→CANN）的 runtime 依赖不由该句覆盖。正文不可把 AscendCL 写成「等价于 CUDA runtime 的全场景层」。
- **cuDNN/NCCL 的「独立产品」是结构性证据**：12.8 组件表全文无 cuDNN/NCCL（负面核对）+ 独立文档树 + NGC Contents 分列；没有一句官方声明直说「cuDNN/NCCL 不属于 CUDA Toolkit」，正文按证据形态表述。cuDNN 9.7.0.66、NCCL 2.25.1 的独立版本化归档页未取得（cuDNN 归档站仅到 8.9.7；NCCL 归档有 nccl_2275 等但与 25.01 的 2.25.1 不同版）。
- **CUDA 12.8 文档站内口径差异（非冲突）**：release notes Table 1 把「NVIDIA Linux Driver 570.86.10」列为组件行（随发布捆绑的驱动版本），安装指南 meta-packages 表称 `cuda-toolkit-12-8` 不含驱动、`cuda-runtime-12-8` 含驱动包——前者是发布捆绑口径、后者是元包依赖口径，正文分列。meta-packages 表 `cuda-12-8` 行残留「Remains at version 12.5」字样，疑模板缺陷，不引用。
- **ROCm 文档站标题与组件表冲突（沿用 batch-16）**：HIP 站标 7.16.0 vs 组件表 10.1.0；llvm-project 站标 22.0.0 vs 组件表 24.0.0。正文引用组件版本以 release notes 组件表为准并注明文档站差异。
- **PyTorch ROCm 框架能力的分发渠道分叉（沿用 batch-16）**：上游 wheel 索引 ROCm 目录只到 rocm7.14；ROCm 10.x wheel 由 AMD 索引分发。框架能力格的措辞必须是「AMD 分发带 rocm10.1.0 本地版本标识的 wheel」，不能写成上游 wheel 已覆盖。
- **PyTorch on ROCm 的通信库表述缺口**：get-started 页未展开 ROCm 后端用 RCCL；「PyTorch ROCm 使用 RCCL」的上游精确表述本轮未取证，对照矩阵该交叉点标 partial。
- **vLLM 树内平台职责页未取证**：CUDA/ROCm 在 vLLM 为树内平台的结论来自 plugin 文档 OOT 定位的反推与 ROCm release notes 生态表；docs.vllm.ai 的 supported hardware/platforms 页本轮未打开，正文如需强表述应补。
- **hiascend 可变页与站点缺陷（沿用既有口径）**：83RC1 树页头版本选择器显示 8.3.RCX（JS 渲染），与 URL 路径不一致；document/detail 页服务端标题存在占位/错渲染缺陷。本批版本绑定依据 URL 路径段 + 正文版本字符串（如 yum 示例中的 8.3.RC1），引用一律带观察日期。
- **实测列全空**：三栈六域的「实测」格均为 `not_run`；本批全部证据为文档级。验收标准 3 的「unknown/conflict 可追踪」在正文中应落到：CANN 编译器组件页（unknown）、CANN 8.3.RC1 精确 HDK 交集（blocked，batch-15 记录）、PyTorch×RCCL 表述（unknown）、vLLM 树内平台页（unknown）、HIP/llvm 站标冲突（conflict）、cuDNN/NCCL 独立归档（unknown）。
