## 缺口与冲突

- **CUDA 12.8 归档构建缺陷**：`group__CUDART__DEVICE.html`（Device Management，含 cudaDeviceSynchronize/cudaSetDevice/cudaGetDeviceCount 函数级参考页）在 12.8 HTML 归档返回 404，modules 页仍链接该地址；同归档 PDF 的目录只有「6.2 Device Management [DEPRECATED]」而正文缺 Device Management 章节。本批以 PG §3.2.8.5.3（cudaDeviceSynchronize 语义）与 PDF §6.34（初始化/复位语义）替代；live（非归档）docs 页存在但未核对版本，不作固定引用。
- **「sticky error」术语缺口**：在 CUDA 12.8 的 PG、Runtime API（HTML+PDF）、Driver API Error Handling 页均未检索到 "sticky" 字样；12.8 文档的错误模型以「异步错误由后续不相关调用报告 + 每线程错误变量（Get 复位/Peek 不复位）」表达。正文若需 sticky/不可恢复错误概念，须另找固定版本来源（新版 CUDA 文档或驱动行为说明），不得倒填进 12.8 引文。
- **hiascend document/detail 渲染异常**：`aclcppdevg_03_0022.html`（aclInit）的 detail 页服务端 `<title>` 错渲染为 CANN 9.0.0-beta.2 的另一页面标题（`__half2ll_rd`），但其内嵌 `doc_center/source/zh/CANNCommunityEdition/82RC1alpha001/...` 内容地址正确、正文为 aclInit 且页内交叉链接均在本版本树；另有多个 detail 页（0039/0056/0144/0020 等）服务端标题仅为门户占位「昇腾社区官网」。版本绑定结论：URL 路径段 + doc_center/source 内容 + 同树交叉链接三重一致，detail 标题异常按站点缺陷记录；此前 83RC1 同路径抓取失败的既有结论（src.huawei.cann-82rc1alpha001-acl-runtime-memory notes）不变。
- **API 不等价点（正文不得宣称一一等价）**：(1) CANN 无 `aclrtQueryEvent`，实际接口为 `aclrtQueryEventStatus`（出参枚举 ACL_EVENT_RECORDED_STATUS_COMPLETE/NOT_READY），且未 record 的 Event 查询返回 COMPLETE（0083/0086 页），与 CUDA/HIP「未 record 查询返回成功」措辞相近但状态语义经出参表达；(2) `aclrtStreamQuery` 以出参 `aclrtStreamStatus` 返回状态、函数返回值是 aclError，CUDA `cudaStreamQuery` 直接以返回码 cudaErrorNotReady 表达；(3) HIP `hipDeviceScheduleBlockingSync` 在 ROCm 平台是 Yield 同义词、hipDeviceSynchronize「尚不支持多阻塞模式」，与 CUDA `cudaEventBlockingSync`/CU_CTX_SCHED_* 的阻塞语义不同；(4) HIP `hipStreamDestroy` 的销毁时机有两种可能——队列可在仍有 in-flight 命令时被销毁、或等全部命令完成后再销毁；该段无任务取消保证（2026-10-09 按 B15-C05 修订，删除「命令随队列删除」的旧概括），CUDA `cudaStreamDestroy` 为「资源待完成后自动释放」的延迟回收；(5) CANN `aclrtRecordEvent`/`aclrtStreamWaitEvent` 自称异步接口（成功仅表示下发成功）而 CUDA `cudaEventRecord` 文档按「捕获 stream 内容」描述、未用同一措辞。销毁、同步、资源释放三个概念已定向复核：CUDA 销毁=立即返回+延迟回收（Stream Management 页）、同步=`cudaStreamSynchronize`/`cudaDeviceSynchronize`（阻塞语义见 PG §3.2.8.5.3）、释放=完成时自动；HIP 销毁=两种时机可能、同步=host 阻塞至 stream empty、释放=未在 stream_management 页单独承诺；CANN 销毁=显式 `aclrtDestroyStream`/随 `aclrtResetDevice`、同步=`aclrtSynchronizeStream`、释放=复位时默认 Context/Stream 下任务完成后再释放（0040 页）。
- **滚动 URL 来源**：NCCL（观察时 2.32.3）与 cuDNN（观察时含 SM100/9.x 内容）文档首页为 latest 滚动页，职责表述稳定但页面不可作不可变快照；正文引用带观察日期，或后续改为归档版本（NCCL 归档至 nccl_2xx、cuDNN 归档至 8.9.7）。
- **样例仓库状态**：CANN 8.2.RC1.alpha001 指南与 ResNet-50 样例页链接的 gitee.com/ascend/samples 已标注「停止维护、迁移至 gitcode.com/cann」（gitee API 确认仓库描述，2026-10-09 观察）；gitcode 新仓未核对，正文引用样例时须注明旧链状态。rocm-examples 默认分支为 amd-staging（可变），必须引用固定 commit 58fd61ac。
- **示例覆盖度**：三平台官方示例中仅 CUDA vectorAdd 含显式数值结果校验；CANN 指南流程含同步与拷回但校验逻辑在样例工程中（ResNet-50 top5 后处理，非数值断言）；HIP saxpy/streams 不含校验。「最小初始化→运算→同步→结果检查」方法定义可组合三栈语义写出，但「结果检查」环节只有 CUDA 示例有直接官方背书。
- **未取证项**：HCCL（CANN 通信库）职责页、CANN 驱动（HDK）边界、HIP↔ROCR 版本对应、CUDA 12.8 之外版本的初始化行为差异（12.0 变化点已引 PG 原文）；T02-02 source_discovery 中「HDK 驱动边界」一项本轮未取得，保持缺口。
