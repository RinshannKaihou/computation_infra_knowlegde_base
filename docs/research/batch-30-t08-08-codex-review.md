## 编号发现

### C01 · P2 · ZTDR 不能作为 abstention 反面的度量

- **位置**：方法 L84；关联 L66、L81 及题组 L99。
- **问题**：将 ZTDR 直接等同于“abstention 反面”，混淆了是否调用工具与证据不足时是否拒绝确定归因。调用过一次工具后仍可能武断下结论；面对固定输入直接正确弃答，也可能没有工具调用。该映射会误奖强行归因、误罚合格的 U 级答案。
- **证据**：[Cloud-OpsBench v1 §4.2.2](https://arxiv.org/pdf/2603.00468v1#page=12)（印刷页 12 / 文件页 12）定义的是未作任何有效工具调用便生成最终结果的 episode 比例，没有把它定义为选择性弃答指标。其统计对象与本库 U 级判据不同。
- **建议修订**：保留 ZTDR 为该交互式基准中的取证过程指标；将其与 abstention 分开，按案例可判定性和回答是否过度确定评价弃答。公开固定输入题也应允许依据已有证据正确弃答。
- **关闭条件**：删除等同关系；“有工具但无证据仍确定归因”和“无工具但正确保留 unknown”两种回答不会再被 ZTDR 替代判定。无需执行评测。

### C02 · P2 · 冻结规则把被比较变量的变化一概判为不可比

- **位置**：方法 L42；关联 L29、L43、L92。
- **问题**：把知识库版本、模型/配置、评分规则一并冻结后，又写“任何一项变更……旧分数不可比”。模型、提示词或知识库版本往往正是评测要比较的变量；只因候选模型变化便禁止比较，会使这份规范无法回答 L29 所问的诊断质量改进问题。新一轮有新标识，与不能作受控比较不是同一件事。
- **证据**：[Cloud-OpsBench v1 §3.2、§4.1、Table 4 及 §4.6](https://arxiv.org/html/2603.00468v1#S3.SS2)在同一冻结环境和评价口径下比较不同模型及知识增强方式；[V12 method_steps](../../plans/validation-backlog.yaml) L483–485 要求固定记录版本与规则，没有要求候选对象一变便永久失去可比性。本项为对规范内部用途的独立判断，不把论文实验当本库已运行结果。
- **建议修订**：区分固定的测试输入/oracle/评分口径与预先声明的候选变量；逐轮保留模型、配置、知识版本及独立性记录。测试条件变化时重评共同候选或停止直接比较，候选对象变化则按同一协议比较。
- **关闭条件**：规范能说明两个模型或两版方法在何种共同条件下可比，以及输入/答案/rubric 变化后何时必须重新建立基线；不混用不同试卷的裸分。

### C03 · P2 · PTF-04 的命令失效机制与 DNS 判据超出复盘

- **位置**：题组 L69–71。
- **问题**：输入增加“在骨干路由器全量下发且撤销未生效”，把审计工具未阻止危险命令写成了事后撤销失败；判据又要求“DNS 服务器离线”导致维护通道不可用。这会把正确指出服务器仍运行、命令下发机制未知的回答判成不符合标准。
- **证据**：[Meta 原文](https://engineering.fb.com/2021/10/05/networking-traffic/outage-details/)中容量评估命令段只披露命令使全部骨干连接断开、审计工具因缺陷未正确阻止；随后 DNS 段明确服务器仍在运行，只因撤回 BGP 广播而不可达。恢复段分别披露许多内部工具受 DNS 影响和主用/带外访问失效，没有给出所有运维通道的共同 DNS 依赖链。[兄弟案例](../../knowledge/08-reliability/correlated-failure-source-case.md) L42–44、L70、L82 已保留这些区别。
- **建议修订**：输入使用容量评估命令、审计阻止失败、全部骨干连接断开的披露范围；判据区分进程运行、对公网不可达、内部工具依赖和网络访问失效。共享控制路径是本库归纳，具体下发/撤销机制继续 unknown。
- **关闭条件**：准确复述原文并保留未知的回答可以得分；不再以“全量下发、撤销失败、DNS 进程离线或所有维护通道均因 DNS 失效”为必答事实。

### C04 · P2 · PTF-06 混合 float32 ABFT 与 bf16 比对观察

- **位置**：题组 L83–86；取证记录 L21。
- **问题**：输入把 float32 ABFT 几乎不触发与“逐元素比对显示持续存在不一致”并置，未说明后者来自另一精度/实验，容易被读成同一工作负载下的同步漏检证据。“持续”还扩大了原研究所示的节点间差异和间歇尖峰。由此不能把本题当作已测得同条件假阴性率的 oracle。
- **证据**：[arXiv:2502.12340v1 D.1–D.3](https://arxiv.org/pdf/2502.12340v1#page=16)（印刷页 16 / 文件页 16）明确区分 float32 ABFT 与 §4.2 的 bfloat16 子模块失配，特别说明两者发生率不必对应；D.3 是可能解释。§4.2 还记录部分节点该设置下无失配及不均匀发生。正式 [ACL 版 §4.2](https://aclanthology.org/2025.acl-long.996.pdf#page=6)（印刷页 20377 / 文件页 6）也保留精度区别。
- **建议修订**：分别列出已知不健康节点、bf16 比对观察、float32 ABFT 结果与其不可直接对照的限制；把“持续存在”收缩到实际节点/窗口或改为非持续的观察。三种解释保持假设性质。
- **关闭条件**：输入和判据明确 dtype/实验分离；正确拒绝将两组结果直接配对计算漏检比例的答案应获认可，仍可据已知缺陷说明“未触发不等于健康”。

### C05 · P2 · PTF-07 把单次快照比例升级为同型集群参照区间

- **位置**：题组 L90–92。
- **问题**：先否定任意集群外推，随后却把“作为同型集群的参照区间”列为正确用法。原文提供的是特定快照内的分类比例，没有给出供其他集群使用的区间。机型相同仍不足以固定负载、运行阶段、筛查策略及归因口径；该判据会要求答题者作另一种未经支持的外推。
- **证据**：[Llama 3 v3 Table 5、§3.3.4](https://arxiv.org/pdf/2407.21783v3#page=13)（印刷页 13 / 文件页 13）限定为该次预训练的 54 天意外中断分类，并保留已确认/疑似归因；没有跨集群预测区间或通用 SDC 风险区间。[统计兄弟篇](../../knowledge/08-reliability/reliability-metrics-and-recovery-loss.md) L149 也明确不能作为任何集群的预期值。
- **建议修订**：仅作为带完整条件的来源观察或提出调查假设的背景；明确 1.4% 的条件分母是该快照的意外中断，不是卡、集群、时间或所有未被发现 SDC 的风险分母。
- **关闭条件**：不再把“同型集群参照区间”当标准答案；保持平台、窗口、分母和疑似归因的回答可得分，不要求未经证实的区间迁移。

### C06 · P2 · PTF-08 的本地复现情境没有来源或合成标注

- **证据**：[Llama 3 Table 5](https://arxiv.org/pdf/2407.21783v3#page=13)只记录来源方快照；[V12](../../plans/validation-backlog.yaml) L479–489 的资源、证据和执行记录均未提供这起本地事件。任务 acceptance 第三条要求合成夹具明确标注；AGENTS.md 禁止补造本地事故历史。这是缺少来源/标注的发现，不是断言该本地事件必定没有发生。

### C07 · P2 · 九题数量达标，但缺少可验收的存储诊断覆盖

- **位置**：题组 L20、L46–109，尤其 L48–50；取证记录 L35。
- **问题**：现有题目主判据分布为训练状态恢复、集合通信、推理部署/设备映射、平台网络、硬件/正确性和未知归因。唯一 checkpoint 题 PTF-01 要识别的是缺失 optimizer state 的框架语义，并明确排除数据损坏，没有存储路径、文件完整性、持久化或 I/O 的判别输入/oracle。不能仅凭出现 checkpoint 一词就认定已覆盖存储诊断。
- **证据**：[任务 acceptance 第二条](../../plans/full-coverage-backlog.yaml) L7081 明列存储；[归属规则](../../content-outline.md) §5 将 checkpoint 文件传输/持久性归 04，状态、恢复点及优化器一致性归 06。[固定 DCP 修订](https://github.com/pytorch/pytorch/blob/edd8d356b6d9a00cfa34fa323578e5cf1c7e0463/torch/distributed/checkpoint/state_dict.py#L1009-L1017)也只修 optimizer state 的存在性分支。本项是依据实际判分内容的覆盖审计，不要求每域独占一题。
- **建议修订**：补充或调整至少一条以存储诊断为实际判分内容的公开题，配固定证据、oracle、unknown 条件与 rubric；也可在既有题加入有独立证据支撑的存储分支。仅改标题/领域标签不足以关闭。
- **关闭条件**：能逐项给出六类场景和无法判定样例的题号映射，存储一栏有可核对的观察与判据；总题数仍至少八条，新增合成内容准确标注，仍不充当 holdout。
