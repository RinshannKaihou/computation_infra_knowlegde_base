## 缺口与冲突

- **Xid 表结构版本差异**：现行目录（2026-09-09 更新）的四个 YES/NO 列是 A100/H100/B100/GB200 产品适用性；2020 年前后旧版用 HW Error/Driver Error/User App Error/System Memory Corruption 归因列。两套结构并存于第三方转载中，正文只按现行版本引用，归因只从 Trigger Conditions 与 XID 144-150 Decode 表的 HW/SW、Local/Remote 列取。
- **Xid 目录自述局限**：含义跨驱动版本一致，但 PCIe/显存损坏可表现为几乎任何 Xid；目录是调试出发点，不是根因判决；文档持续新增条目（143 起 CUDA 12.9/R575、162–172 等新行），固定引用须带观察日期。
- **分诊表与目录口径差**：GPU Node Triage Table 1 把 Xid 31 描述为 "Suspected Hardware Problems"（动作导向），目录 Trigger Conditions 说通常应用级 bug；含义以目录为准，动作表用于处置流程。
- **DCGM 退出码混合语义**：226 是「诊断跑完且报错」，215/217/204 等是「调用/启动失败」，205 是「需要隔离」；非零码不能单独判硬件根因（registry B12-C01，本轮复核一致）。
- **昇腾三套码不可混**：npu-smi Health 五态（状态摘要）、DCMI 返回码（API 调用结果，-8001~-8255，检测链语义）、设备故障码（黑匣子码族 0x……与健康管理事件 0x80E2xxxx 两族）分属三类证据；UNKNOWN=设备不存在或未启动，不是故障判决；恢复事件（0x96183207 等）与故障事件是不同码，不可合并为状态翻转。
- **昇腾检测前提差异**：黑匣子码的「检测条件」分在线上报/复位后上报/检查上报——复位后上报类事件在复位前在线不可见；健康管理事件在 npu-smi health -c 最多保留最近 8 次，更早事件只在 msnpureport/黑匣子日志侧；阈值数值与 ACG/POWERBRAKE 分表未公开。
- **AMD 无 Xid 式全目录**：公开材料只有 AFID 列表（category/type/severity，20 条）且明示部分事件无需立即处理、详情联系服务商；无公开逐码处置/阈值表，AMD 分支的「影响解释」只能到 severity 与 category 层级，不可仿照 Xid 表编造处置动作。
- **AMD 复位语义不可外推**：`amd-smi reset --gpureset` 在 XGMI hive 内是 hive 级动作，ROCR_VISIBLE_DEVICES 不构成隔离；与 nvidia-smi --gpu-reset 的单卡语义（且按架构/FM/虚拟化分档）不同，两家的「reset」不可合并叙述。概念页指向内核 GPU recovery 文档的链接与目标内容不符（driver-misc.html 无 recovery 内容），内核侧恢复文档缺口已记录。
- **AMD 版本错配是一等 N/A 来源**：驱动 gpu_metrics 版本新于 AMD SMI 时相关字段读 N/A（ROCm 7.13 起支持 v1.9 动态布局）；N/A 三分的归类规则（2026-10-09 第二轮修订）：Not Applicable=覆盖边界；Not Available=数据不可用，不直接赋予失败类别——不支持/不提供归覆盖边界、查询失败归采集失败、解析错配单独记录、原因不明记 unknown；Empty Section 区分「无条目」与「整节查询失败」；CSV 全设备缺报时整组省略列、仅部分缺失才填 N/A，缺列不得解释为零值/正常/已覆盖。
- **时间线对齐无官方端到端样例**：OCP v1.0 给出「同一事件带内带外双记录+CPER/Redfish」的需求，GB200 发布说明给出双通道共存与去重的案例证据，Xid 79 注释给出「查系统事件日志」的方法指引，但没有官方文档展示 BMC 事件、Xid/CPER、作业事件三方带时间戳的完整对齐实例；对齐方法（时钟源、记录 ID、去重）须按「未执行的匹配方法」在正文中如实标注为方法层结论。昇腾 iBMC 告警处理 05 所引事件码条目已于 2026-10-09 第二轮取得原文并逐字核对（明细以 batch-14-bmc-firmware-sources.md 为准）；带外↔带内码官方对应关系仍未取得、待补。证据链边界（第三轮标注）：所引码为编写者经渲染提取取得并逐字核对的记录，独立审阅者两轮均未取得原文、未独立核验，不据此单独建立处置规则。
- 时钟可信度：amd-smi 文档示例 CPER 时间戳为占位值（2000/06/27）；Xid 依赖内核日志时间戳、CPER 依赖固件/平台时钟、Redfish 事件依赖 BMC 时钟——三处时钟源的对齐前提各来源均未声明，正文须列为记录字段（observed_at + 时钟源）而非默认已对齐。
