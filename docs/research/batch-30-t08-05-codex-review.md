## 编号发现

### C01 · P2 · 用均值模型的规划方法承接 p99 不确定性，缺少适用假设

- **位置**：正文 L68、L70、L74、L135；取证记录 L10。
- **问题**：L74 紧接“分位数估计”给出“用初始实验方差反推重复数（§7.4）”，会使读者把均值的方差/成本规划当成 p99 样本规划。该段也只举正态性，未交代所用模型的独立重复单位及层级依赖；一般请求流和同一进程迭代不能自动视为独立样本。
- **证据**：[原 PDF](https://arxiv.org/pdf/2007.10899#page=29) §7.4（印刷/文件页 29–30）优化均值区间的精度；§7.2–7.3 针对均值/均值比，§7.1 和 §7.2.1 另有层内及层间独立性假设。bootstrap 输出中取分位点，不等于原文证明了延迟 p99 的区间或样本量算法。
- **建议修订**：分开均值比和尾分位。保留“无通用 N”，明确尾部估计对象、抽样/重复单位、依赖与失败请求口径；选用并登记能支持该估计对象的方法，或把具体区间/样本规划保持待定。原论文公式只在其适用模型下使用。
- **关闭条件**：读者不能再由 §7.4 推出通用 p99 所需样本数；选定区间方法及其假设可定位，相关独立性限制写明；不得用增加相关迭代数冒充增加独立重复。

### C02 · P2 · 把 SuperBench 的离线学习判据写成“完全前置”的预注册样板

- **位置**：正文 L76、L145；取证记录 L19。
- **问题**：build-out 全集结果先被测得，再用于学习判据；它不能证明这批数据执行前阈值/判据已经全部冻结。正文把学习期和后续应用期合并成“完全前置”，削弱了本篇关于避免事后改判据的核心要求。
- **证据**：[SuperBench PDF](https://www.usenix.org/system/files/atc24-xiong.pdf#page=9) §3.4、Algorithm 2（印刷页 842 / 文件页 9）先由全集结果学习，后续验证才与离线判据比较；§3.1（印刷页 840 / 文件页 7）还说明周期更新判据。
- **建议修订**：改为明确的“学习/校准后固定，用于后续验证”样板；区分用于定判据的数据与用于评价结果的数据，标明判据身份、冻结时点和再校准触发。预注册是本库要求，不能由无监督学习这一事实推得。
- **关闭条件**：正文与取证记录区分两个阶段，不再宣称 build-out 自身展示了全部判据在测量前冻结；更新判据后对应验证范围可追踪。

### C03 · P2 · 用测试类别直接给出低风险和分钟级成本

- **位置**：正文 L49–54，尤其 L53–54。
- **问题**：验收对象包含新/返修节点及整套栈，却被统一写成“分钟级、低、只读查询为主”；基准也统一为低风险。主动诊断“另计”的括号没有说明此时验收只完成了哪一层。作为选择矩阵，这会低估整机诊断、供电/散热负载和通信/存储基准的资源与恢复要求。
- **证据**：本文链接的[节点验收](../../knowledge/01-hardware/node-acceptance-triage.md) L43、L90–92 将主动诊断、基准列为验收组成并标高影响；原厂 [DCGM Run Levels and Tests](https://docs.nvidia.com/datacenter/dcgm/latest/user-guide/dcgm-diagnostics.html#run-levels-and-tests) 区分长短级别及 stress/power/memtest。它们不支持统一分钟级预算。NCCL 方案 L108–115 也要求隔离实际计算/网络资源。
- **建议修订**：按所选层级、具体工具/负载、持续时间和共享域记录成本/风险；只读层可以单列。基准须写计算、内存、网络或存储占用及结束后的资源/配置核对，预算未知保持 unknown。
- **关闭条件**：用一个被动验收和一个整机主动诊断/通信基准代入矩阵，能得到不同的资源、风险、隔离和恢复要求；不由“验收/基准”名称直接推出低风险或固定耗时。

### C06 · P2 · 清缓存的三倍条件缺少比较对象，并隐藏上游条款与示例冲突

- **位置**：正文 L71、L143；取证记录 L16；registry `src.mlcommons.storage-rules-v2.0` notes。
