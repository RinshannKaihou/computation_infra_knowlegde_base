## 编号发现

### C01 · P2 · MTBF/MTTF 区分及分布假设混淆

- **位置**：正文 L56–59、L151；取证记录 L25、L30。
- **问题**：把 MTBF 与 MTTF 的区别归结为“是否已计入修复期”并不成立，也没有提供实际采用的计算定义。将这些均值一概写成默认 i.i.d.，又把“年龄相关的非常数 hazard”直接等同于破坏 i.i.d.，混淆了描述性均值、更新过程与指数/HPP 推断。是否能计算一个样本摘要，与能否据此外推或给出特定置信区间不是同一问题；MTTR 还应讨论恢复时长样本，而不是统称故障间隔。
- **证据**：NIST 的[可修复/不可修复对象定义](https://www.itl.nist.gov/div898/handbook/apr/section1/apr121.htm)与 [§8.4.5.1 的 HPP/exponential 模型](https://www.itl.nist.gov/div898/handbook/apr/section4/apr451.htm)明确区分对象和模型，后者估计量的分子为系统运行时间，并非自动加入修复停机。[Weibull 公式](https://www.itl.nist.gov/div898/handbook/apr/section1/apr162.htm)同时给出非常数 hazard 和有限均值。审阅者反例：独立抽取同一 Weibull 分布的寿命仍为 i.i.d.，故非常数 hazard 本身不能推出非 i.i.d.。
- **建议修订**：给出本文采用的 MTBF、MTTF、MTTR、MTBI 的对象、时间轴、事件数和停机处理；分开描述性统计与更新/指数模型推断，明确独立性、同分布及恒定事件率分别需要什么证据。保留不默认满足假设的纪律，并为这些基础定义补登记统计原始来源。
- **关闭条件**：不再以修复期是否计入作为 MTBF/MTTF 的唯一或固有区别；能按明示公式计算同一事件表，且不再把非恒定 hazard 等同于非 i.i.d.。取证记录同步说明已核定义与仍未覆盖的检验方法。

### C02 · P2 · Table 5 的原始冲突被误限于 HTML，“只用百分比”不能证明统计自洽

- **位置**：正文 L59、L67、L157；取证记录 L9、L32；registry L7047。
- **问题**：正文虽在末尾披露 148 与 30.1% 不一致，却将问题限为 HTML 渲染，并以 GPU 六行百分比求和自洽作为引用依据。原版 PDF 也有同一冲突；六行相加为 58.7% 只证明表内加法对应，不能证明它们与 419 次事件或完整分类自洽。L59/L67 未就近说明 58.7% 是论文报告值、与计数存在未解冲突。
- **证据**：[Llama 3 v3 PDF，Table 5 与 §3.3.4，印刷页 13 / 文件页 13](https://arxiv.org/pdf/2407.21783v3#page=13)和 [v3 HTML](https://arxiv.org/html/2407.21783v3)均列相同数字。本轮逐行复算：18 行绝对计数合计 **419**；百分比合计 **94.9%**；GPU 六行计数 **268**，268/419＝**63.9618%**；148/419＝**35.3222%**，而表写 30.1%；GPU 百分比六行相加才是 58.7%。不能据此判定究竟哪列应改。
- **建议修订**：将 58.7%、30.1% 等明确标为“论文报告值，计数/百分比未能共同核实”，在采用处就近披露；或删去本篇不必使用的细分比例。保留 466＝47＋419 等可复核主链，记录冲突也存在于 v3 PDF；不得自行把 35.3% 或 64.0% 当成作者勘误后的真值。
- **关闭条件**：正文、取证记录、registry 一致保留来源冲突，不再称为仅 HTML 问题或整体统计自洽；每个保留比例都能区别“原文报告”与“独立计数核实”。

### C03 · P2 · 把故障前作废计算与成功重放混为零产出，合成例账目未闭合

- **位置**：正文 L83–85、L136、L140；取证记录 L25。
- **问题**：L85 将重算/回放一概称为“产出为零”，L136 又断言恢复后的 3 h 重算产出作废。正常从有效 checkpoint 重放并保存会推进恢复后的状态；作废的是之前未保留下来的尝试。若新尝试也作废，需另给失败原因或单独声明评价目标为超过故障前高水位的新增进度。当前“有效进展”“高水位追平”“满足四维判据的健康时间”被混用为同一 161 h。进程存在时长 165.5 h 也未由明确的进程创建/退出时刻推出。
- **证据**：[MPG v1 §4.3 Runtime Goodput，印刷页 8 / 文件页 8](https://arxiv.org/pdf/2502.06982v1#page=8)排除的是最后 checkpoint 到失败之间未保存的工作；[OCP §5.3.1，页 21 / 文件页 21](https://www.opencompute.org/documents/sdc-in-ai-ocp-whitepaper-final-pdf#page=21)描述回到此前正确状态。正文自己的 L83 又把进入最终状态或 checkpoint 的进展列为有效。纯算术上 168−2−0.5−1.5−3＝161；161/168＝95.8333%，165.5/168＝98.5119%，差 2.6786 个百分点均算对，但这些运算不能证明各时间段的业务含义。
- **建议修订**：分别标出故障前丢弃的尝试、成功保留的重放、追平故障前进度的时刻和恢复可承接工作的时刻；说明统计窗口是否包含原先那 3 h。为进程存活另给时间段并集。可保留合成数字，但应让每段只按所选口径计入一次。
- **关闭条件**：同一时间线能独立重算最终保留进展、重复计算资源成本、服务可用性及健康窗口；成功且保留的重放不再无条件记为零产出，165.5 h 有可追溯的事件边界。

### C04 · P2 · fleet 例遗漏 32 起事件的重叠条件，并把 RG 开销归入 SG

- **位置**：正文 L73–75、L145；取证记录 L25。
- **问题**：“32 张卡各一起事件”没有说明同一作业的事件是否同时、重叠或先后发生，却只乘一次 512×5 h。另将加载、预热和资源齐备时的重放全部归为 SG 损失，违背前文 MPG 定义。160 卡·时与 2560 卡·时是两种受影响范围下的损失分子，并非仅更换分母；正文没有实际写出两个比率。L75 的“PG 与故障无关”也把计量分层过度解释成了根因隔离保证。
- **证据**：[MPG v1 §4.3，印刷页 8–9 / 文件页 8–9](https://arxiv.org/pdf/2502.06982v1#page=8)以全体资源同时可用为 SG 分子，将初始化、加载、编译等列入 runtime 层；PG 的分母是实际执行时间，不给出故障无关保证。本轮按作者暂定的每事件 5 h“总损耗”复算：32×5＝160 卡·时；若 32 个影响区间完全重合，作业并集才为 5 h，512×5＝2560 卡·时；若完全不重叠，并集为 160 h，512×160＝**81920 卡·时**。同一 512 卡、168 h 的容量分母为 **86016 卡·时**，上述量不能互换。
- **建议修订**：明确事件/对象集合及影响区间，按并集计算作业损失，并明确是资源不可用、运行损耗还是净进展损失；给出实际分母和比率。将资源齐备后的加载/重放等按明示状态划入 RG，收缩“PG 与故障无关”的绝对说法。
- **关闭条件**：至少给出一种无歧义的重叠设定，能逐事件复算卡级与作业级值；SG 不因仅有重放就扣减，分子、分母和量纲完整，且不再把分层指标当作互斥故障分类。

### C05 · P2 · 检出并回滚不足以推出正确性无损，SDC 也不推出重算为零

- **位置**：正文 L141，并关联 L136、L143。
- **问题**：从“错误被检出并回滚”直接推出“正确性无损”，缺少恢复点早于污染、状态一致、错误源被移除及恢复后校验通过等前提。“未检出 SDC 污染 checkpoint，则 3 h 重算变 0 h”也不是必然：同样的崩溃重启仍可能从较早的污染 checkpoint 重放，耗时与污染是两个独立记账量。合成例允许设定条件，但需将设定写明，不能把它写成一般因果结论。
- **证据**：[OCP §5.3.1，页 21 / 文件页 21](https://www.opencompute.org/documents/sdc-in-ai-ocp-whitepaper-final-pdf#page=21)的回滚前提是此前正确状态；[SRE “Errors”](https://sre.google/sre-book/monitoring-distributed-systems/#the-four-golden-signals)区分显式成功与内容正确。库内[Checkpoint 状态一致性](../../knowledge/06-training/checkpoint-state-consistency.md) L111–119 要求状态/数据进度核对和恢复后验证；[处置选择](../../knowledge/08-reliability/mitigation-and-recovery-principles.md) L108–114 同样不把回滚视为验证完成。
- **建议修订**：为两条合成分支明确恢复点、污染时刻、重放区间和校验结果；“正确性无损”改成这些判据通过后的有限结论。污染固化可以说明有效产出判定失效，不应自动将恢复计算耗时清零。
- **关闭条件**：同一症状下的正确性差异由显式证据/合成前提决定；污染状态和回放时长分别记录；没有“已回滚＝正确”或“SDC＝零重算”的推理。

### C06 · P2 · 将实际恢复耗时写成 RTO，并无条件减半单次重算

- **位置**：正文 L143，并关联 L47–48、L136、L140。
- **问题**：由一次分段耗时相加得到的是本例实际恢复时长，不能直接定义目标 RTO。且本例“可承接工作”又等到追平 3 h 后才恢复，2 h 与 5 h 分别到哪个终点未对齐。checkpoint 间隔减半也不能无条件推出这次 3 h 重算变 1.5 h；需要失败相位、保存完成点和重放速度等条件。
- **证据**：NIST 的 [Recovery Time Objective 定义](https://csrc.nist.gov/glossary/term/Recovery_Time_Objective)把它定义为业务可容许的恢复期，不是事后样本和。正文算式 0.5＋1.0＋0.5＝2.0 h 算对；若终点是完成追平，则为 2.0＋3.0＝5.0 h。反例为审阅者推导：周期从 6 h 改为 3 h，故障仍在共同 checkpoint 后 0.5 h 发生，则两种策略都丢 0.5 h，并不减半；均匀失败相位下的期望或最坏上界需另行声明。
- **建议修订**：将目标 RTO 与实际恢复时长分列，明确开始、服务恢复和追平进度三个坐标；把减半结论改为有条件的期望/上界比较，或给出完整合成相位后重新计算。
- **关闭条件**：目标与观测量分别命名；2 h/5 h 终点与可用性口径一致；没有由 checkpoint 周期直接决定某次重算量的无条件结论。

### C07 · P2 · 训练错误预算迁移把好产出写作通用分母

- **位置**：正文 L100。
- **问题**：“分母从请求换成有效训练时间或已保存 step”没有给出总机会量及好/坏事件划分，易把产出损失从分母中一起排除。以有效时间或已保存进展自除，可能在没有产出时得到无定义，在大量失败工作被排除后仍显得健康。已保存 step 可以是某种条件性质量 SLI 的样本总体，但不能直接替代长期产出/可用性预算的总量。
- **证据**：[Implementing SLOs，“What to Measure: Using SLIs”](https://sre.google/workbook/implementing-slos/#what-to-measure-using-slis)要求好事件/总事件；[MPG v1 §4.3](https://arxiv.org/pdf/2502.06982v1#page=8)也明确区分 productive、allocated 与 capacity。正文 L67 本身使用有用训练时间/经过总时间，L100 的迁移没有保留这个结构。
- **建议修订**：先定义训练 SLI：如有效保留时间/合格的总日历或分配时间，或合格进展/纳入考核的全部进展机会；说明失败尝试、维护、回放和零样本处理。若只考核已保存 step 的正确性，明确这个条件性范围以及另需记录的产出损失。
- **关闭条件**：给出至少一组完整分子、分母、单位、SLO 和预算消耗规则；故障未产生进展不会被静默排除或记成 100% 达标。
